TEMEL KURALLAR

- Bir adımın "Beklenen" kısmı sağlanmazsa: ALT ADIMLARA GEÇME, [ON_ERROR] bloğunu uygula.
- Komutlar bu dosyada birebir verilmiştir; kendi kafana göre değiştirme.
- Beklenen sonuç belirsiz kaldıysa tahmin etme: [ON_ERROR] uygula ve bana sor.

0. SABİTLER VE ORTAM
-------------------------------------------------------------------------------
PROJE_WIN = C:\angularAndJava\on_muhasebe\on-muhasebe-spring-boot
PROJE_WSL = /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot
CONTAINER = pre_accounting_db

DB_USER   = bozlak      (compose.yaml -> POSTGRES_USER)
RUN_LOG   = target/run.log

Ortam bilgisi:
- İşletim sistemim Windows, WSL2 üzerinde Ubuntu var. Maven ve Docker SADECE WSL içinde
  kurulu (Windows tarafında değil).
- İnteraktif bir CMD/WSL penceresinin açık kalacağını VARSAYMA. Her komut kendi kendine
  yeterli olmalı ve şu kalıpla çalıştırılmalı:
      wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && <komut>'
  Önceki bir 'cd'nin veya set edilmiş bir değişkenin hâlâ yaşadığına güvenme.
- Projede Spring Boot Docker Compose Support var. 'mvn spring-boot:run' compose.yaml'ı
  ayağa kaldırır ve bağlantı bilgilerini application.properties'teki spring.datasource.*
  ayarlarının ÜZERİNE yazar. Yani uygulama on_muhasebe_db'ye DEĞİL, container içindeki
  test_db'ye bağlanır. SQL'ler de test_db'ye gitmek zorunda. Adım 3 bunu doğrular.
- 'mvn spring-boot:run' terminali bloke eden bir komuttur. Bu yüzden Adım 2'de arka planda
  ve logları dosyaya yazacak şekilde başlatılır; böylece uygulama ayaktayken aynı shell'den
  docker/psql komutları verilebilir.

-------------------------------------------------------------------------------
2. UYGULAMAYI BAŞLAT
-------------------------------------------------------------------------------
2a. Arka planda başlat, PID'i kaydet, tüm logları target/run.log'a yaz:
  wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot || exit 1; mkdir -p target; nohup mvn spring-boot:run > target/run.log 2>&1 & echo $! > target/app.pid; sleep 2; cat target/app.pid'

2b. Başlamayı bekle (5 saniyede bir kontrol, en fazla 240 saniye):
  wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && for i in $(seq 1 48); do if grep -q "Started OnMuhasebeSpringBootApplication in" target/run.log; then echo HAZIR; exit 0; fi; if grep -qE "BUILD FAILURE|APPLICATION FAILED TO START|Error starting ApplicationContext" target/run.log; then echo BASLATMA_HATASI; exit 1; fi; sleep 5; done; echo TIMEOUT; exit 1'

Beklenen: çıktı "HAZIR".
"BASLATMA_HATASI" veya "TIMEOUT" -> [ON_ERROR].
Not: 240 saniye, ilk koşuda Maven'ın dependency indirmesi için verilmiş bir üst sınırdır.
Sonsuza kadar bekleme; süre dolarsa bu bir hatadır.


-------------------------------------------------------------------------------
3. VERİTABANINI VE TABLOLARI DOĞRULA
-------------------------------------------------------------------------------
3a. Container ayakta mı:
  wsl -e bash -lc 'docker ps --filter name=pre_accounting_db --format "{{.Names}} | {{.Status}} | {{.Ports}}"'
Beklenen: pre_accounting_db, "Up ...", port eşlemesi 0.0.0.0:5433->5432/tcp.

3b. Tablolar doğru veritabanında oluşmuş mu (Spring Data JPA, ddl-auto=update):
  wsl -e bash -lc 'docker exec pre_accounting_db psql -U bozlak -d test_db -c "\dt"'
Beklenen: en azından 'users' ve 'admins' tabloları listelenmeli.
Tablolar YOKSA uygulama başka bir veritabanına bağlanmış demektir -> [ON_ERROR].
(Bu kontrol atlanırsa SQL'ler boş/yanlış bir DB'ye gider ve pipeline "başarılı" görünür.)

3c. users tablosu boş mu:
  wsl -e bash -lc 'docker exec pre_accounting_db psql -U bozlak -d test_db -tAc "SELECT count(*) FROM users;"'
Beklenen: 0. Değilse -> [ON_ERROR] (Adım 1'deki id varsayımı bozulmuş).

ayrıca admins.who_created_admin_id kendi satırına referans verir, yani admin_id=1.)

===============================================================================
 [ON_ERROR] — hata bloğu
===============================================================================
Bir adım başarısız olduğunda bu bloğa girilir. Bu bloğa atıf yapabilirim, context'inde kalsın.

1. DUR. Sonraki adımlara geçme. Hatayı kendi başına "düzeltmeye" çalışma.
2. Uygulamayı HENÜZ kapatma; önce logları topla (kapatırsan logları kaybedersin):
     wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && { echo "SONUC: HATA"; echo "HATA ADIMI: <adim numarasi>"; echo "CALISTIRILAN KOMUT: <komut>"; echo "BEKLENEN / GORULEN: <kisa aciklama>"; echo "TARIH: $(date -Iseconds)"; echo "----- docker ps -a -----"; docker ps -a; echo "----- run.log (Maven + Spring tum loglar) -----"; cat target/run.log; } > errors.txt && ls -l errors.txt'
   (<...> yerlerini gerçek değerlerle doldur.)
3. [CLEANUP] bloğunu uygula.
4. Beni uyar: hangi adımda patladı, hatanın özeti (log'daki ilgili satırlar) ve errors.txt'in
   yolu. Kendi kafana göre alternatif bir yol denemeden bekle.


===============================================================================
 [CLEANUP] — kapatma bloğu
===============================================================================
Hem başarılı bitişte hem hata durumunda, loglar yazıldıkTAN SONRA uygulanır.

1. Uygulamayı nazikçe durdur (SIGTERM). 'kill -9' KULLANMA; graceful shutdown gerekiyor:
     wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && kill $(cat target/app.pid)'

2. Kapanma loglarını bekle (en fazla 60 saniye):
     wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && for i in $(seq 1 12); do if grep -q "Shutdown completed" target/run.log; then echo KAPANDI; exit 0; fi; sleep 5; done; echo KAPANMA_TIMEOUT; exit 1'
   Beklenen: HikariPool'dan "Shutdown initiated..." ve "Shutdown completed." logları.
   NOT: Süreç sinyalle sonlandırıldığı için Maven "BUILD SUCCESS" yazmayabilir. BUILD SUCCESS'i
   zorunlu kriter sayma; kriter "Shutdown completed" + container'ın Exited olmasıdır.

3. Container'ın durduğunu doğrula:
     wsl -e bash -lc 'docker ps -a --filter name=pre_accounting_db --format "{{.Names}} | {{.Status}}"'
   Beklenen: "Exited (...)". Docker Compose Support, uygulama kapanırken container'ı durdurur.
   Hâlâ "Up" ise (sadece bu durumda izinli):
     wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && docker compose stop'

4. Container'ı sil ve sildiğini doğrula:
     wsl -e bash -lc 'docker rm pre_accounting_db && docker ps -a --filter name=pre_accounting_db'
   Beklenen: ikinci komutun çıktısı boş (başlık satırından başka satır yok).

5. Arkada süreç kalmadığını doğrula:
     wsl -e bash -lc 'pgrep -fa "spring-boot:run" || echo TEMIZ'
   Beklenen: "TEMIZ". Süreç kaldıysa PID'ini bana bildir.
