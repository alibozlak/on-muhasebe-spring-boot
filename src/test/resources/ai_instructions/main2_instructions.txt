KARAKTER KODLAMA (Türkçe karakterler) — ÖNEMLİ:
Gerçek kullanımda "Müşteri" gibi Türkçe değerler giriliyor, o yüzden testler de Türkçe
veriyle yapılır. ASCII'ye ("Musteri") çevirme; çevirirsen kodlama hatalarını test etmemiş
olursun. Kurallar:

  a) Shell zinciri UTF-8'i bozmuyor (ÖLÇÜLDÜ: Windows tool -> wsl -> bash zincirinden
     "Müşteri" 9 byte olarak, 4d c3 bc c5 9f 74 65 72 69 dizisiyle geçiyor). Yani komut
     içine Türkçe karakteri doğrudan yazabilirsin.

  b) URL QUERY PARAMETRESİNDE percent-encoded (UTF-8) yaz. Swagger UI de tam olarak bunu
     yapıyor; Swagger'ın ürettiği curl şuydu:
       curl -X 'POST' \
         'http://localhost:8080/api/v1/contact-types/create-contact-type?contactTypeName=M%C3%BC%C5%9Fteri' \
         -H 'accept: */*' -H 'Authorization: Bearer <token>' -d ''
     Yani "Müşteri" -> M%C3%BC%C5%9Fteri. Ham Türkçe karakteri URL'e koyma; percent-encoded
     hali kesin ve tarayıcının gönderdiğiyle aynı olan biçimdir.
     Yeni bir değerin karşılığını hesaplaman gerekirse:
       wsl -e bash -lc 'python3 -c "import urllib.parse;print(urllib.parse.quote(\"Müşteri\"))"'

  c) JSON GÖVDESİNDE Türkçe karakteri düz yaz (percent-encoding YAPMA, JSON gövdesi
     UTF-8 taşır): -d "{\"contactName\":\"Ahmet Yılmaz\"}"

  d) DB doğrulamasında sadece göze güvenme. Terminal/psql çıktısı doğru görünürken byte'lar
     bozuk olabilir. [KALIP-5] ile byte uzunluğunu ve hex'i karşılaştır.

[KALIP-1] Token alma (login):
  wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && curl -s -o target/login_admin.json -w "HTTP:%{http_code}\n" -X POST http://localhost:8080/api/login -H "Content-Type: application/json" -d "{\"username\":\"bozlak\",\"password\":\"bozlak\"}" && python3 -c "import json;print(json.load(open(\"target/login_admin.json\"))[\"object\"][\"jwtToken\"])" > target/jwt_admin.token && wc -c target/jwt_admin.token'

[KALIP-2] Token'lı POST/PUT çağrısı (gövdeli):

  Tırnak notu: dış tırnaklar tek tırnak, JSON içindeki tırnaklar \" olarak yazılır;
  bash bunları normal " haline getirir. Tek tırnak KULLANMA (dış tırnağı kapatır).

[KALIP-3] Query parametreli çağrı (gövdesiz, ör. contact-types):
  wsl -e bash -lc 'cd /mnt/c/angularAndJava/on_muhasebe/on-muhasebe-spring-boot && curl -s -o target/last_response.json -w "HTTP:%{http_code}\n" -X POST "http://localhost:8080/api/v1/contact-types/create-contact-type?contactTypeName=M%C3%BC%C5%9Fteri" -H "accept: */*" -H "Authorization: Bearer $(cat target/jwt_admin.token)" -d ""; echo "--- body ---"; cat target/last_response.json; echo'

  Bu, Swagger UI'ın ürettiği curl'ün birebir karşılığıdır: aynı percent-encoded query
  parametresi, aynı "accept: */*" başlığı, aynı boş gövde (-d ""). Endpoint @RequestParam
  ile çalışıyor, JSON gövdesi beklemiyor.

[KALIP-4] Veritabanı doğrulama:
  wsl -e bash -lc 'docker exec pre_accounting_db psql -U bozlak -d test_db -c "SELECT ...;"'
  Tek satır/tek değer karşılaştırması için: psql -tAc "SELECT ...;"

[KALIP-5] Kodlama doğrulama (Türkçe karakter içeren her alan için ZORUNLU):
  wsl -e bash -lc 'docker exec pre_accounting_db psql -U bozlak -d test_db -tAc "SELECT contact_type_name, char_length(contact_type_name), octet_length(contact_type_name), encode(convert_to(contact_type_name,'\''UTF8'\''),'\''hex'\'') FROM contact_types WHERE contact_type_id=1;"'

  TIRNAK KURALI (ÖLÇÜLDÜ, tahmin değil): psql sorgusunun içindeki tek tırnaklar '\''
  olarak yazılır. Okunuşu: dış tek tırnağı kapat ( ' ), kaçışlı tek tırnak koy ( \' ),
  dış tek tırnağı yeniden aç ( ' ). Bash bunu tek bir ' karakterine indirger.

  '' (iki tek tırnak) YAZMA. Bash '' dizisini "tırnağı kapat, hemen yeniden aç" diye
  okur, yani boş stringdir ve tırnaklar TAMAMEN KAYBOLUR. Ölçüm:
      girdi : echo "SELECT ''contact_type'' kaynak, convert_to(x,''UTF8'')"
      çıktı : SELECT contact_type kaynak, convert_to(x,UTF8)        <- tırnak yok
      girdi : echo "SELECT '\''contact_type'\'' kaynak, convert_to(x,'\''UTF8'\'')"
      çıktı : SELECT 'contact_type' kaynak, convert_to(x,'UTF8')    <- doğru
  Tırnaklar kaybolunca psql 'UTF8' string sabiti yerine UTF8 SÜTUNUNU arar ve
  "ERROR: column ... does not exist" verir.

  $$...$$ (dollar-quoting) da KULLANMA: bash $$ ifadesini çift tırnak içinde bile
  kendi PID'ine genişletir ( $$contact_type$$ -> 24895contact_type24895 ).

  Beklenen değerler (ÖLÇÜLDÜ, tahmin değil):
    Müşteri       -> char=7   octet=9    hex=4dc3bcc59f74657269
    Ahmet Yılmaz  -> char=12  octet=13   hex=41686d65742059c4b16c6d617a

  octet_length = char_length çıkıyorsa Türkçe karakterler yolda kaybolmuş demektir
  (ör. "Musteri" veya "M?steri" yazılmıştır) -> [ON_ERROR]. Ekranda doğru görünmesi
  yeterli kanıt DEĞİLDİR; kriter hex eşleşmesidir.

===============================================================================
 MODÜL DOSYASI SÖZLEŞMESİ (yeni bir <modul>_instructions.txt yazılırken uyulacak format)
===============================================================================
Bu bölüm, T2'deki modül dosyalarını yazarken kullanılacak şablondur. Yeni modül
eklenirse hem bu şablona uyulur hem de T2 tablosuna satır eklenir.

1. Başlık: modülün adı, hangi endpoint'leri kapsadığı.
2. Giriş/çıkış: "Buraya main2_instructions.txt T2'den gelinir, bitince T2'ye dönülür."
3. Adım numarası formatı: <MODUL_KISA_AD>.<n>   (örn. USER.1, USER.2, ACCOUNT.1)
4. Her adım şu üç parçayı içerir:
     KOMUT        : birebir çalıştırılacak wsl komutu (T1'deki kalıplardan biri)
     BEKLENEN     : HTTP kodu + cevap gövdesi (success alanı, hata mesajı)
     DB DOĞRULAMA : psql sorgusu + beklenen satır/değer
   DB doğrulaması olmayan adım yazma; Swagger'da 201 görüp DBeaver'a bakmamak gibi olur.
5. Log tablosu doğrulaması: ana kayıt hangi log tablosuna yazıyorsa o da doğrulanır.
6. En az bir negatif test: yetki (403), validation (400) veya kimlik (401).
7. Sabit veriler T1'den alınır; modül kendi test verisini uydurmaz. Türkçe karakter içeren
